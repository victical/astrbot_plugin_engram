### P0-2: 删除操作缺乏原子性保证

**问题描述：**
`delete_memory_by_id` 执行顺序：
1. 备份到 `deletehistory` (SQLite)
2. 从 Chroma 删除向量
3. 删除/标记 `RawMemory` (SQLite)
4. 删除 `MemoryIndex` (SQLite)

**风险：**
- 步骤 2 成功但步骤 3 失败 → 向量已删除但原文还在
- 步骤 3 成功但步骤 4 失败 → 原文已删除但索引还在
- 撤销删除时遇到不一致状态 → 数据损坏

**修复建议：**
```python
def delete_memory_by_id(self, index_id, delete_raw=False):
    # 1. 开启 SQLite 事务
    with self.db.atomic():
        # 2. 先备份（事务内）
        backup = self._backup_for_undo(index_id)
        self.db.save_delete_history(backup)
        
        # 3. 删除 SQLite 数据（事务内）
        if delete_raw:
            self.db.delete_raw_memories_by_uuids(ref_uuids)
        else:
            self.db.mark_as_unarchived(ref_uuids)
        self.db.delete_memory_index(index_id)
        
    # 4. 事务提交后再删除向量（失败不影响 SQLite）
    try:
        self.collection.delete(ids=[index_id])
    except Exception as e:
        logger.warning(f"向量删除失败（已记录）：{e}")
        self.db.enqueue_pending_vector_jobs("delete", index_id)
```

### P0-3: 并发归档可能产生重复记忆或数据竞争

**问题描述：**
- 调度器每 60 秒检查一次归档
- 用户可手动执行 `/归档记忆`
- 无并发控制机制
- `unsaved_msg_count` 在多线程下可能不准确

**风险：**
- 同一批消息被总结两次 → 重复记忆
- 归档期间新消息的计数错误 → 消息丢失
- 数据库写入竞争 → SQLite 锁超时

**修复建议：**
```python
import threading

class MemoryManager:
    def __init__(self, ...):
        self._archiving_lock = {}  # {user_id: Lock}
        self._archiving_lock_global = threading.Lock()
    
    def check_and_summarize(self):
        for user_id in active_users:
            # 获取用户级锁
            with self._archiving_lock_global:
                if user_id not in self._archiving_lock:
                    self._archiving_lock[user_id] = threading.Lock()
                lock = self._archiving_lock[user_id]
            
            # 尝试获取锁（不阻塞）
            if not lock.acquire(blocking=False):
                logger.debug(f"用户 {user_id} 正在归档中，跳过本次")
                continue
            
            try:
                self._summarize_private_chat(user_id)
            finally:
                lock.release()
```

## P1 - 功能逻辑错误/严重影响核心功能（4 项）

### P1-1: 群聊记忆会话隔离配置语义冲突

**问题描述：**
用户同时配置：
```json
"group_memory_store_session_as": "group_id",      // 按群存储
"group_memory_private_session_only": true         // 强制按用户隔离
```

两个配置互斥但可以同时设置，文档说第二个优先级高，但配置界面没有联动提示。

**影响：**
- 用户困惑：为什么我按群存储不生效？
- 配置错误难以排查
- 违反"最少惊讶原则"

**修复建议：**
```python
# 方案 1：简化为单一配置
"group_memory_session_mode": {
    "type": "string",
    "options": ["by_group", "by_user"],
    "default": "by_group"
}

# 方案 2：增加配置校验
def validate_group_memory_config(config):
    if (config.get("group_memory_store_session_as") == "group_id" and
        config.get("group_memory_private_session_only") == True):
        logger.warning(
            "⚠️ 配置冲突：group_memory_private_session_only=true "
            "将覆盖 store_session_as=group_id，实际按用户隔离存储"
        )
```

class LLMContextInjector:
    def inject_context(self, event, profile_block, memory_block, tool_hint_block=None):

        else:
            # 追加到系统提示词（原逻辑）
            event.unified_msg_origin = f"{event.unified_msg_origin}\n\n{injection_text}"

### P1-4: 群聊好友白名单冷启动问题

**问题描述：**
- 配置 `group_memory_only_friends: true`
- 插件启动时 `FriendCacheService` 好友列表为空
- 需要等待 OneBot `friend_add` 事件或手动刷新
- **启动后的群聊消息全部被过滤，用户不知道原因**

**影响：**
- 群聊记忆功能看起来"不工作"
- 用户需要手动触发好友列表刷新（但没有文档说明）
- 重启插件后又需要重新初始化

**修复建议：**
```python
# services/friend_cache.py
class FriendCacheService:
    def __init__(self, config):
        self._friends = set()
        self._initialized = False
        self._init_task = None
    
    async def ensure_initialized(self, context):
        """确保好友列表已初始化"""
        if self._initialized:
            return
        
        if self._init_task is None:
            self._init_task = asyncio.create_task(self._load_friends_from_onebot(context))
        
        await self._init_task
    
    async def _load_friends_from_onebot(self, context):
        try:
            # 调用 OneBot API 获取好友列表
            friends = await context.get_friend_list()
            self._friends = {f["user_id"] for f in friends}
            self._initialized = True
            logger.info(f"✅ 好友列表初始化完成，共 {len(self._friends)} 人")
        except Exception as e:
            logger.error(f"❌ 好友列表初始化失败：{e}")
```

## P2 - 性能/可靠性问题（3 项）

### P2-1: ChromaDB 初始化可能阻塞主线程

**问题描述：**
- `_ensure_chroma_initialized()` 在首次检索时同步执行
- 大量数据时加载慢（可能 5-10 秒）
- 阻塞 LLM 请求 → 用户感觉机器人"卡住"

**修复建议：**
```python
# 在插件启动时后台预热
class EngramPlugin:
    def __init__(self, ...):
        # 后台预热 Chroma
        self._create_background_task(
            "chroma_prewarm",
            self._prewarm_chroma()
        )
    
    async def _prewarm_chroma(self):
        await asyncio.sleep(5)  # 等待主流程稳定
        try:
            await asyncio.to_thread(
                self.logic._memory_manager._ensure_chroma_initialized
            )
            logger.info("✅ ChromaDB 预热完成")
        except Exception as e:
            logger.warning(f"ChromaDB 预热失败：{e}")
```

### P2-2: 记忆检索缓存策略不完善

**问题描述：**
- 话题缓存 TTL 120 秒
- 用户新产生的记忆归档后，缓存不会失效
- 场景：用户刚说了 A，立刻问"我刚才说了什么"，但 A 还在缓存中，新记忆未归档

**影响：**
- 新记忆不被召回 → 用户觉得机器人"失忆"

**修复建议：**
```python
# 在归档完成后清除相关缓存
class MemoryManager:
    def _summarize_private_chat(self, user_id):
        # ... 归档逻辑 ...
        
        # 归档完成后清除话题缓存
        if hasattr(self, '_topic_cache_service'):
            self._topic_cache_service.clear_user_cache(user_id)
            logger.debug(f"已清除用户 {user_id} 的话题缓存")
```

### P2-3: 画像更新提示词过于复杂（100+ 行）

**问题描述：**
- 提示词包含 11 条原则 + 5 条规则 + 7 条标签规则 + 详细示例
- 占用大量 token（约 1500-2000 tokens）
- LLM 难以完全遵守所有规则

**影响：**
- Token 成本高
- LLM "选择性失明"，忽略部分规则
- 画像更新效果不稳定

**修复建议：**
```python
# 拆分职责：
# 1. Prompt 只负责"提取信息"
# 2. ProfileGuardian 负责"验证规则"
# 3. 后处理负责"标签简化"

SIMPLIFIED_PERSONA_PROMPT = """
你是用户信息提取助手。从记忆中提取明确提及的事实。

【当前档案】：{{current_persona}}
【新增记忆】：{{memory_texts}}

【规则】：
1. 只提取记忆中直接写出的信息
2. 不推测、不联想、不脑补
3. 保持原有字段不变（除非记忆中明确提到）

输出 JSON（不要 Markdown）：
"""

# 标签简化在代码中处理
def simplify_tags(tags: list) -> list:
    """限制标签长度为 2-5 字"""
    return [t[:5] for t in tags if 2 <= len(t) <= 5]
```

## P3 - 配置/文档不一致（3 项）

### P3-1: 配置项数值范围缺失验证

**问题描述：**
- `memory_similarity_threshold: 2.1`（文档建议 1.0-2.0）
- `private_memory_timeout: 500`（默认 1800）
- 无运行时校验，填错难以排查

**修复建议：**
```python
CONFIG_CONSTRAINTS = {
    "memory_similarity_threshold": (0.5, 3.0),
    "private_memory_timeout": (60, 7200),
    "min_msg_count": (1, 50),
}

def validate_config(config):
    for key, (min_val, max_val) in CONFIG_CONSTRAINTS.items():
        value = config.get(key)
        if value is not None and not (min_val <= value <= max_val):
            logger.warning(
                f"⚠️ 配置项 {key}={value} 超出推荐范围 [{min_val}, {max_val}]"
            )
```
